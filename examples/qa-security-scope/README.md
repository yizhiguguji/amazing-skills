# 安全范围模拟演练

这是技能库的合成验证，不是要推广的产品，也没有真实服务、个人、公司、设备或凭证。来源、范围、身份和策略只在本示例生效，不能固化进共享技能。

## 模糊请求与调度评阅

维护AI按新入口/技能内容对下列真实风格的输入做语义评阅；这是作者侧评阅，没有独立AI自动路由评测。Go回放使用下面的合成计划验证记录约束，不实现自然语言关键词路由。

| 模拟输入及上下文 | 选择与交付 | 保持的边界 |
| --- | --- | --- |
| r1昵称需求：“帮我出用例，看看有没有安全风险” | qa-test-design：正向、边界、已有归属规则、预览文本检查；会话策略列gap | 不造密码/支付/上传用例，未知会话不填30分钟或401 |
| 同一昵称需求：“安全上再仔细看看” | qa-security-review：仍仅昵称范围，复用已有ID，审查相关安全来源与验证章程 | 不自动扫描全站；只有来源中的模型授权可执行对应合成动作 |
| 无需求/项目：“全面测一下安全” | qa-security-review先澄清目标，给出需要确认的对象/执行边界 | 不猜系统、账号或工具，不生成可执行攻击清单 |
| 只改保存按钮文案：“出点用例，安全也考虑” | qa-test-design验证文字、布局和本期可操作性，记录无鉴权行为变更 | 不重测完整登录/角色系统 |
| r2：“长度改了，预览不要了，更新一下” | qa-test-design变更分析：TC-001/002修订2，TC-004 retired，TC-003/005保持 | 旧通过不继承新修订，不删除历史、不填补未知策略 |
| 只有用例：“汇总一下安全结论” | qa-test-report输出覆盖/准备情况及未执行；有本回放记录时输出synthetic-only | 不把计划/模型通过当真实应用安全结论，不自动建Jira |

## 可执行回放结果

`run/replay-results.json`是实际Go程序产生的结果；`run/.qa/cases.md`、`coverage.md`是实际导出。来源为sources/r1.md、r2.md。

- r1四条ready，一条未知会话策略proposed。模型预置跨用户读取缺陷，记录失败；修复后同轮重试passed，汇总仍为3 passed / 1 failed。
- r2长度上限12→20，预览撤回。候选变更为TC-001/002/004；TC-003/005保持；撤回保留历史，两个新修订未执行。
- 明确模型目标与动作授权后，r2独立复测TC-003通过；当前轮为1 passed / 2 not-run，另列1 proposed / 1 retired。历史失败不删除。
- 负向检查拒绝范围外目标、未知预期被写成固定ready，以及只有设计ready但缺专项执行授权的正式结果。
- 模型测试的HTML编码不是浏览器XSS验证；没有真实请求、扫描、设备、Jira或标准合规结论。

执行：

```bash
go run ./cmd/amazing-skills security-replay --output /新的临时目录/security-demo
go run ./cmd/amazing-skills qa export-cases --project /新的临时目录/security-demo
```

程序拒绝覆盖已有目录。可用已安装Go独立程序替换go run前缀；正常运行不需要Go编译器或Python。
