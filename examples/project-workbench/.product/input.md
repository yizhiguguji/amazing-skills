# 合成评测输入

原始模糊需求：我接了几个小项目，消息和进度散在不同地方，总不知道今天该先推进哪个，帮我弄个工作台。

本样例由维护者构造，用于用户要求的完整技能接入验证，不代表真实产品客户。结构化模拟回答：
- 主对象：项目；使用者：一个自由职业者；任务：早上找超期项目、改进度、记下一步。
- 范围：本地单人网页原型；技术选择交给实现者，无发布和外部提交。
- 方案选择：项目看板为主，五个用途明确的导航；明亮办公场景，克制的青绿色、系统中文字体；代码先行，无图像资产。
- 验收：数据真实派生、刷新保留、键盘可用、移动端不溢出。

后续合成需求（第二轮）：加一个按交付日期筛选的小工具，只影响看板，不改变整体设计、字体、颜色和组件。

评测边界：执行模型实际读取三个上游技能，并运行两个上游工具；交互采用上述结构化模拟回答。不是在无人回答时把假设当成用户确认，也不是跨机器实测或对技能效果的统计评估。
