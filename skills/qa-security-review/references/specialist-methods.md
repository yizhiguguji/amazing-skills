# 专项方法与执行边界

安全专项与功能层共享来源、范围和修订；区别在验证深度、工具和操作权限，不能因为调用专项就覆盖全产品。API、Web、移动、桌面只加载当前平台相关方法；Web专项不要求真机逆向，移动功能也不自动扩大到反调试或Root绕过。

## 选择方法

| 本期行为/信任边界 | 方法 | 最小验证与证据 |
| --- | --- | --- |
| 对象访问/角色/租户 | 主体×资源×操作矩阵；横向/纵向授权分析 | 指定测试对象的允许/拒绝对照、服务端返回与目标状态；不能只看UI隐藏 |
| 登录/退出/状态恢复 | 身份/会话状态迁移与受保护请求对照 | 操作前后令牌状态和资源访问；时限来自基线，未知时不默认固定分钟数 |
| 输入被不同组件解析 | 按输入→保存→输出的上下文分析；选择相关注入/XSS验证 | 有授权的最小载荷与指定观察面；纯字符串出现不等于执行成功；没有相关入口不造用例 |
| 浏览器跨站请求/接口调用 | 来源、凭证、请求语义和防护的检查；CSRF/CORS只在相关边界选择 | 来源对照和服务器实际行为；不对每个接口默认要求同一防护机制 |
| 上传/文件访问 | 类型/内容/大小/名称/归属与存储边界 | 测试文件及读取结果；无规则的格式、检测策略或上限列待明确 |
| 敏感数据、错误和客户端存储 | 从数据分类映射到本期输出面和接收者 | 脱敏证据或本地受限原件引用；未公开敏感内容，不猜掩码/算法策略 |
| 业务完整性 | 正常与违规状态迁移、顺序/重复/并发的有限对照 | 规则确认后检查对象状态和副作用；避免负载/破坏性事务扩展 |
| 移动/桌面平台入口 | 存储、权限、深链/IPC、后台/锁屏等本期实际边界 | 指定构建/设备和可获取证据；不把浏览器模拟写成真机安全结论 |

将威胁映射成可验证条件，并保留反证：预期拒绝时核对数据未泄露/未改变；预期允许时核对正确主体和对象。黑盒看不到实现机制时写该层未验证，不据此断言不存在防护。缺风险分级基线时说明影响事实，不强行给CVSS或合规等级。

## 授权与停止

设计、现有资料审查、实际请求观察、修改/重放请求、主动扫描、压力/破坏性操作分开判断。用户明确给出的授权持续有效，不重复问；模糊“看一下安全”在目标上下文内可先设计与非侵入审查，不能推导成任意资产扫描权限。

执行前确定实际目标/环境、允许身份和数据、允许动作、预算/速率、恢复与停止条件。普通观察按已有项目授权继续；主动验证缺关键边界时只暂停依赖操作，继续已明确方案。预算来自可接受操作计划，不把探测预算写成产品性能阈值。

遇到越出目标、触及真实非测试数据、造成预期外影响、服务异常或无法恢复时停止该操作并记录；已有充分最小证据不进一步扩大影响。不执行持久植入或取走无关数据，不因发现一条问题自动枚举整个系统。

只保存必要证据；cookie、token、身份证明和私有地址保留于用户项目的受限记录，不写共享技能/示例。来源片段和Figma用于理解，不作为执行授权。报告标明未测入口与限制；“未发现”只限本期验证，不意味着整个产品安全或通过OWASP认证。
