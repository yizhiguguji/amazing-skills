# 功能安全检查：范围内的风险筛选

适用于通用功能测试，不绑定产品、公司或账号系统。安全是相关场景的标签，不新增第12个强制功能维度，也不为每个需求生成整套安全用例。

先从本期功能找出主体、资源、操作、输入、输出和状态；记录哪些行为实际改变。每个候选必须能说明“这个变更如何影响这个安全行为”。仅文案/样式修改一般不重测鉴权；没有账号或共享数据的功能不编造角色和越权入口。沿用已确认的同功能安全基线，并引用其具体条款和版本。

| 需求涉及 | 相关候选 | 可观察结果与依据 |
| --- | --- | --- |
| 登录、退出、身份切换或受保护操作 | 未登录访问、失效会话、退出返回、切换身份后的数据残留 | 按确认的身份/会话规则检查显示、服务端结果、资源状态；缓存画面与成功读取分开记录 |
| 所有者、角色、租户、分享、导出 | 同角色跨对象、跨角色、跨租户、链接与直接入口 | 仅用已存在且允许的测试身份；角色×对象归属×操作矩阵，分别验证读/写；按钮隐藏不代表服务端授权正确 |
| 自由文本、搜索、富文本、链接 | 符合现有输入规则的特殊字符、存储后显示、转义/解析上下文 | 源明确时验证保存/显示；没有格式规则就记录缺口，不默认“所有特殊字符必须被拒绝”。输入安全不等于任意攻击载荷执行授权 |
| 文件上传、下载、预览 | 已定义的类型/大小/访问权限、取消与异常恢复 | 边界按明确单位和包含关系；文件扫描、危险内容策略未知则待明确，不猜格式黑名单或限制大小 |
| 敏感字段、错误提示、通知、导出 | 来源已标明的敏感信息在本期输出面暴露 | 明确哪个字段、哪个输出面、哪个接收者；未定义敏感级别/掩码位置进入缺口，不擅自定义掩码位数 |
| 保存、支付、重复点击、异步处理 | 范围内的数据完整性、幂等与重放风险 | 功能操作按已确认规则验证；修改请求、重放和绕过客户端移交专项执行边界，不从普通用例请求推导授权 |
| 移动应用缓存、后台、锁屏、剪贴板或深链 | 本期数据在指定状态/平台上的可见性与访问 | 仅当涉及相应能力时选择；平台权限拒绝/撤销属于相关功能路径；未知锁屏遮罩、截屏限制或清理策略不写固定预期 |

## 依据和决策

候选决定为 include / not-applicable / clarify / deferred，始终写理由。需求已给安全条款时纳入；只发现合理风险但判定规则未知时写问题或探索目标，不升级成正式验收。WSTG、ASVS、MASVS提供方法，不自动采纳等级、超时、密码强度、加密方式或错误码。若项目明确采用某标准，记录版本、适用条款、裁剪范围及确认来源。

正式用例须有：范围内资源/操作、真实可准备身份/数据、当前需求或确认基线、可观察预期。每个安全断言引用具体需求修订及来源位置。经验推断不充当预期依据。未知策略保持 proposed/deferred 和 gap；探索只记事实与风险，不能写passed或“漏洞已确认”。

同一目标已有负向/边界/状态用例时添加security元数据，复用稳定ID，避免复制。直接API检查不可仅靠UI截图证明；工具或访问不可用则标未验证，不先要求开发造测试桩。

变更时比较主体/资源/操作/权限/数据出口及判定依据。语义改变增加用例修订；撤回保留retired；旧执行不计新修订通过。未知项澄清后再转ready，不用旧探索观察补写通过。

没有既有管理系统时，采用 [安全数据扩展](security-contract.md) 保存候选决策、范围和判定来源。无需强制业务系统迁移到这个JSON。
