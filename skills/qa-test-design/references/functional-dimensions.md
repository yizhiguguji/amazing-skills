# 功能测试维度：相关性先于数量

每个维度记录 `include / not-applicable / clarify / deferred`、具体理由、需求/确认基线和场景或缺口。简单任务也考虑候选，但“不适用”可合理且短小；用户限定范围时记录限制和风险。

| 维度ID | 何时相关 | 核对事项与边界 |
| --- | --- | --- |
| interaction | 本期涉及控件/页面 | 可点击、连续点击、取消返回、焦点、真实热区、状态文字和布局；Figma已明确的相关视觉 |
| happy | 有合法操作 | 完成主流程及数据回读；不要只看成功提示 |
| negative | 存在拒绝/失败/无权限等路径 | 无效操作被拒绝、数据不变、提示与恢复；不假设不存在的权限系统 |
| boundary | 有范围、长度、计数或时序 | 明确上下界及相邻值；规则未知需澄清，不能自定最大值 |
| state | 行为取决于历史/阶段 | 进入、编辑、提交中、完成/失败、返回的有效转换及重复操作 |
| app-switch | 切换到其他应用会打断相关动作 | 与系统导航切换区别；恢复目标、编辑状态、异步结果是否重复。没有设备则未验证 |
| background | 生命周期影响编辑/异步操作 | Home/后台→前台；按项目预期观察，不假设缓存和进程存活。杀进程与切后台不同 |
| lock | 锁屏/解锁可能中断相关状态 | 锁前/处理中/结果后时机；解锁后直接观察。不能用仅后台事件替代锁屏 |
| offline | 行为使用网络或断网有已知影响 | 请求前/中断/恢复后；真实请求和业务结果、不丢输入、不重复写入须有依据 |
| weak-network | 延迟/丢包/不稳定影响相关请求 | 记录工具、实际profile、延迟/带宽/丢包、切换时机和观察；无规范不编超时或通过阈值 |
| thermal | 持续高负载/已知温度问题影响该行为，或任务明确要求 | 使用允许的正常工作条件和已有监测能力，记录设备、电量、温度来源与时间；无可测指标/阈值不判性能通过，不加全产品压力测试 |

环境变化是测试条件，不自动变成新产品能力。例如切后台时编辑内容是否保留，必须引用当前需求或已确认基线不变量；若未知，列问题而不是默认保留或清空。离线本地纯文案变更通常无需专项弱网；提交服务端数据则网络异常直接相关。

最低可接受环境与真实设备区别：fixture能验证模型中的状态规则，浏览器模拟能验证Web事件/请求；都不能证明原生应用切换、锁屏、射频弱网或发热。报告分别标 `synthetic-fixture`、`browser-emulation`、`real-device` 等模式。OS事件相近仍分别设计，不能合并成“后台/锁屏任一即可”。

热状态、超时、权限等未定义时，先给已确认用例及明确缺口；保留相关风险。无需为了完整表格编造温度、电量、机型、构建或秒数。
