# 保留的专业交付规则

本规则承接经脱敏的原QA技能，去除项目名、私有地址、专属业务与系统实现。角色是职责，不产生账号、审批身份或执行授权。

- 当前用户明确要求与范围优先。项目规定的有效需求/设计/评论是依据；旧用例、聊天和源码辅助取证，不替代业务确认。切换需求重建范围；连续修订沿用确认边界。
- 分开已确认事实、实现观察、假设、覆盖缺口、产品疑问、缺陷、优化建议和无需处理事项。源码推断不是执行结果；性能或请求优化不能用界面正常证明。
- 前置、步骤、预期、依据独立。步骤写真实入口、输入、触发和观察时机；预期写可判断变化或可复算口径，不使用“正确/正常”代替断言。
- 不假定测试桩、可控时钟、请求注入、诊断页、账号或设备存在。先验证入口/工具与数据准备能力，不能要求开发先造工具才能执行普通人工回归。
- 按行为失败影响及项目规范定级；severity与priority分开。不因核心模块所有用例都是最高级，也不按缺陷发现平台限制可跨平台复用的用例。
- 同标题不等于同场景。用触发、状态、数据、动作、观察与断言查重；正式用例已覆盖的缺陷沿用身份，同轮不重复执行扩展。来源关联不是覆盖证明。
- 缺陷草稿、用例评审、可执行资产和结果分别管理。整理人不冒充评审人；项目配置决定免评审与目标状态，不伪造审批、人员或日期。
- 保留首次正式失败，重试通过注明补充结果；准备重试不混入正式执行。复测新建记录，已完成结果与原始证据不改写。冻结快照修订记录原值、原因和授权，旧结论不能证明新步骤。
- 相同范围维护工作稿，不每次编辑制造新送审版本。身份、历史和执行关联不重编号；只改受影响内容，撤回标状态并保留历史。
- 系统接口优先，但工具按实际环境选择。数据库直接写入是显式选用的adapter，需schema、可恢复备份和事务；先核对范围，再写，再回读关系、数量、作者、状态、历史及外键。无适配器不猜表名或直接改数据库。
- 外部授权按动作区分：写用例/执行不自动授权Jira、消息或部署。结果不明先回读，复用已有对象和幂等标识，不盲目重复。
- 证据保存完整且不泄漏凭证。无截图就明确无媒体；不写内部绝对路径、数据库主键、令牌或数据串到外部正文。媒体优先按目标平台支持的方式可见引用/内嵌，核对可访问性、比例与内容；项目不要求媒体的纯文本缺陷不强制造图。
- 报告同一快照复算状态；用例、缺陷和覆盖缺口分别统计。零分母为不适用。未执行不算通过，Jira已完成不等于测试通过。历史趋势与当前修订/轮次分开。
- 语义、数据、呈现与实际运行分别检查。格式校验不能替业务验收，模板生成不能替测试。只在改程序时做相应构建，不给文档任务附加部署。
- 用户纠正先修当前范围；长期规则只在可复用且获授权时更新，不将一次性账号、设备、金额、场景写入共享技能。
