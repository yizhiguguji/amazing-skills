# 按材料提取

## 抽象意图，无参考

先利用上下文推导用户要完成的任务和使用环境；尚不明确的内容标为推断。把“舒服”“专业”“有质感”落到密度、层次、字阶、留白、材质与交互节奏，用一段理由串起来。提供一个连贯可撤销的方向及其适用前提，继续做可查看样例，不把 CSS 参数、完整需求表或风格菜单交给用户。若只有“做个东西”且无法定位对象，先询问目标；不能凭空发明业务模块或数据源。

## 截图 / 图片

记录材料身份、可见区域、尺寸与观察到的层次、色温、间距关系、布局节奏。字体家族、精确色值、遮挡区域、hover、移动端与行为无法从单张图确认，标为推断或未知。提取设计规律，不复制截图内容、品牌标识或受限素材。

## 网站 / 已有代码

确认网址或代码修订及实际工具。浏览器可用时读取代表性页面的 computed styles、字体、变量和组件状态，以截图辅助；代码值不等于浏览器实际呈现。写明页/选择器/状态/尺寸或源码位置。未能访问、鉴权或验证墙导致不可读时记录缺口，继续处理其他证据，不把记忆当测量。来源能访问不代表字体、Logo、图片可重新分发。

## 证据与冲突

design-evidence.json 的每条 claim 标明 kind=observed/provided/inferred、reference、locator、claim、decision 和 token（可选）。kind 表达证据类型，不是模型自信度；observed 必须附包内证据 file 与 SHA256，provided 可用明确会话摘录及定位，inferred 写推断理由及待验证条件。未知项放 unknowns，不用默认值伪装事实。文件路径保持包内相对路径；原始材料含私密信息时只存脱敏摘录，标记展示副本及其局限。

在已有 decisions 中记录保留、改变、不复制及冲突。项目事实与参考不同，以用户已确认目标及项目规范为先；不能让一个新参考静默替换规范。来源之间的关键矛盾无法解开时问具体冲突，其余部分继续推进。

## 行为样例（模型执行检查，不是自动通过记录）

| 输入 | 可观察输出 | 失败/边界 |
| --- | --- | --- |
| “客户跟进页看着太累，想清爽一点”，已有表格和 DESIGN.md | 继承配色，提出信息层次/密度的局部调整，推断标记；提供受影响组件预览 | 不能自造统计或全局重设计 |
| “做个安静的阅读页”，无截图 | 基于阅读任务生成连贯方向、inferred 证据和可撤销包 | 不强迫用户先选样例或填规格 |
| 一张参考截图 | 区分可见规律与猜测，保留/改变/不复制清楚 | 不宣称实测字体或移动端通过 |
| 网址无法访问 | 记录工具失败与未知，继续使用已提供描述 | 不把无法访问当成提取成功 |
| 仅要视觉规范 | 交付包、预览与限制 | 不扩展为产品实现或外部发布 |
