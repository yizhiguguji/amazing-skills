# 工作台验收

读取真实规格、DESIGN.md 与实现。按验收编号逐项检查，记录环境、方法、结果与证据到 `.product/verification.md`。

使用设计系统包时，读取 design-system.json、design-evidence.json、tokens.css 与 design-preview.html，先运行 design-system check --package <项目或包> 检查结构和预览同步。核对推断和 unknowns 是否影响本期验收；结构检查不能把推断变成确认。再核对应用确实导入该 tokens 文件、共享组件的计算样式，以及预览中验证过的状态在真实页面是否成立。预览有变化需重生成；已锁定规范的变更遵循原有设计锁与 decisions，不静默替换基线。

重点：冷启动可行动；数字从实际记录或已连接来源计算；创建/编辑后状态一致且保存有效；外部断开不会变成误导的 0；实际角色权限符合规格；主操作可键盘执行；小屏、长文本、错误状态和无数据可用。测试隔离存储与真实用户数据。

查看实际桌面与移动端渲染，核对主次、规范、字体回退、文字溢出、交互焦点与状态。自动行为通过与人工视觉观察分别记录。截图有尺寸和路由说明；模拟环境不声称真机测试。

发现失败修复后重验失败项及受影响路径。不做无限精修，不为检查添加范围外功能。无浏览器或无法运行时标明未验证，不能只凭读代码认定通过。

完成条件：范围内必要验收全部通过；没有未解决阻断；报告可追溯证据。剩余限制明确记录，若属于必要功能则保持 verify，不写 complete。文档结构校验仅为辅助。
