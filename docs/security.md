# 两层安全能力（通用技能库）

不是某个产品的专用技能：共享目录只保存方法、交接、范围与证据规则。角色、租户、接口、策略、阈值和授权保留在使用者项目；示例为合成材料，不作为其他项目默认需求。

| 层级 | Skill | 调度与结果 |
| --- | --- | --- |
| 功能安全筛选 | qa-test-design内置 | 普通用例请求自动检查本期相关风险；复用负向、边界、状态用例；没有相关变化时说明不纳入 |
| 安全专项 | qa-security-review | 指定功能的安全方案、审查、探索或授权内验证；只加载相关平台/方法，不默认全站扫描 |

模糊说法直接可用：

- “帮这份需求出用例，顺便看看安全”：功能用例加范围内安全筛选，不自动执行或扫描。
- “昵称这块有没有安全问题”：承接当前功能，专项先做资料审查与针对性方案；目标/环境/动作已授权且可用时再验证。
- “重点看看越权”：针对已有对象建立主体×资源×操作矩阵；缺主体/资源只澄清关键事实，不编造角色。
- “再补全面一点”：仍限当前目标，补相关遗漏；不能推导成全产品渗透、扫描或安装工具。
- “需求改了，预览不要了”：保留撤回历史，修订受影响条件，旧通过不继承到新修订。

总入口skill-router和QA入口qa-workflow都能调度；明确指定技能时尊重选择。默认完整安装14技能，QA子包6技能。已有安装需更新快照与二进制，新能力不会自动进入旧副本。

## 范围与预期

每个候选有来源、相关性、决定和理由。确认的需求/同功能基线支撑正式预期；合理风险但规则未知时保留gap和探索目标。未知会话超时、错误码、密码策略、上传限制、脱敏形式不能凭经验写成固定验收。

以昵称需求为例，有明确“只改自己”的基线才形成正式权限用例；存在预览且明确文本显示才选择输出上下文检查。没有角色/上传/支付时不构造这些系统的用例。仅改按钮文案，一般不重新测完整身份系统。

OWASP [WSTG v4.2](https://wstg.owasp.org/v4.2/4-Web_Application_Security_Testing/)、[ASVS](https://owasp.org/www-project-application-security-verification-standard/)、[MASVS](https://mas.owasp.org/MASVS/)用于方法参考，不直接采纳为本期验收或合规目标；详见技能内sources.md，不捆绑标准正文。

## 便携记录与确定性工具

原schema1、11功能维度保持兼容。可选安全扩展记录scope、targets、checks、oracle与专项执行边界，详见 `skills/qa-test-design/references/security-contract.md`。

Go的qa check验证：目标/检查/用例在选定需求范围；关联一致；确认预期引用当前需求；未知预期不ready、不填固定expected；待明确/延期关联缺口。专项执行记录或修改请求等主动动作须有已确认的目标/动作边界；ready不是执行授权。qa export-cases/summary输出安全范围与来源，不宣称全系统安全。

工具只检查结构和保存的引用事实，不理解自然语言语义、不验证真实授权、不证明预期文字正确，也没有攻击执行器或扫描器。AI仍须审核断言依据、目标因果链及实际授权。无预期探索单独记录观察，不强制归类passed/failed。

## 模拟验证

```bash
go test ./...
go vet ./...
go run ./cmd/amazing-skills security-replay --output /全新目录/security-demo
go run ./cmd/amazing-skills qa check --project /全新目录/security-demo
```

独立程序将go run前缀替换为实际安装根`.amazing-skills/amazing-skills`绝对路径。演练嵌入明确合成来源和计划，不需要Go/Python、互联网、真实账号或扫描工具。

[安全范围演练](../examples/qa-security-scope/README.md)检查范围逃逸、未知预期、缺执行授权、同轮失败保留、修订不继承、撤回留历史。它是Go内存模型，不能声称真实应用安全测试；自然语言调度由编排AI执行，语义示例评阅与可执行回归分开记录。
